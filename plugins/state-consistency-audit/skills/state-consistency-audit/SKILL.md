# state-consistency-audit

Models duplicate values across a page and then judge the **source they wrote** instead of the
**rendered, operated result**. The outcomes are familiar: a figure typed as a literal that disagrees
with the computed value on the same row ($12.89 next to $9.39); a rush toggle that regenerates a
number the page elsewhere struck as withdrawn; a total that is not its parts; a `?preset=b` state
nobody ever loaded.

This skill loads the page in its **own isolated headless chromium** (never a shared Playwright MCP
browser), enumerates the states it can reach, puts the page in each one, reads **every text node
including hidden ones and open shadow roots**, and reports each inconsistency with the state that
produced it and both conflicting values. It states findings; it does not decide what they mean.

## Install (once)

```bash
cd skills/state-consistency-audit     # from wherever this plugin is installed
pnpm install                          # playwright-core + axe-core (npm install works too)
pnpm exec playwright install chromium # only if ~/.cache/ms-playwright has no chromium-* yet
node test/run.mjs                     # self-check: positive fixture flagged, negative fixture clean
```

Chromium is resolved without a hardcoded revision (`WEB_PROBE_CHROME` env, else the revision this
playwright-core expects, else the newest `~/.cache/ms-playwright/chromium-*`). Nothing touches the
network at run time. `tools/web-probe.mjs` is a **vendored** copy of the shared harness in
`shared/web-probe`; never edit it here.

## Usage

```bash
node tools/state-consistency-audit.mjs <url|file|dir> <outDir> \
     [--manifest=states.json] [--facts=facts.json] \
     [--totals='#total=#a+#b'] [--pair='#literal=#computed'] \
     [--max-controls=40] [--no-controls] \
     [--block-on=retracted-asserted[,total-mismatch,...]] \
     [--vows=vows.json] [--viewport=desktop|tablet|phone]
```

`<url|file|dir>` is a live URL, an HTML file (its directory is served on a throwaway `127.0.0.1`
port) or a directory with an `index.html`. It writes `<outDir>/report.json`, plus
`<outDir>/evidence/<state>.png` for every state that produced a violation, and prints a summary.

Exit code: `0` normally (the audit is advisory); `2` only if a type named in `--block-on` was found;
`1` on a usage or run error. Without `--block-on` it never fails a build.

Cheapest useful run (controls are auto-discovered, nothing declared):

```bash
node tools/state-consistency-audit.mjs ./dist/index.html /tmp/sca
```

Declare what you know to make it precise:

```bash
node tools/state-consistency-audit.mjs ./pricing.html /tmp/sca \
     --manifest=states.json --facts=facts.json \
     --totals='#total=#base+#ship' --pair='#sticker=#live' --block-on=retracted-asserted
```

### `states.json` (the manifest)

```json
{
  "params":   { "preset": ["a", "b"], "view": ["month", "year"] },
  "presets":  [{ "name": "rush", "params": { "tier": "pro" }, "actions": [{ "action": "check", "selector": "#rush" }] }],
  "controls": true,
  "totals":   [{ "total": "#total", "parts": ["#base", "#ship"] }],
  "pairs":    [{ "a": "#literal", "b": "#computed", "label": "unit price" }]
}
```

- `params` — one state per value (`?preset=b`). Single axis each; list combinations as `presets`.
- `presets` — documented named states, optionally with `params` and/or `actions`
  (`click toggle check uncheck set fill select hover key scroll wait`).
- `controls` — `true` (default) enumerates every operable control on the baseline page: buttons,
  tabs, checkboxes, radios, selects (one state per option), range sliders (driven to min and max).
  A CSS selector narrows it. Controls whose text matches download/print/export/share/submit/buy/pay/
  checkout and `target=_blank` links are skipped. `--no-controls` turns it off.
- `totals` / `--totals='#total=#a+#b'` — the declared total must equal the sum of its parts
  (tolerance 0.01). A part selector that matches many elements is summed.
- `pairs` / `--pair='#a=#b'` — two figures that must be equal in every state.

### `facts.json` (optional source of truth)

```json
{ "_retracted": { "figures": [{ "value": "$709", "replaceWith": "$619", "ruling": "double-counted" }] },
  "quote": { "base": "$1,000", "shipping": "$90" } }
```

Top-level `_`-prefixed keys are prose about the facts and are never harvested as facts. With a facts
file the report also carries `factCheck`: figures found on the page that are exact, one arithmetic
step from the facts, or unsourced. That list is a **question for a human, not a verdict**.

## What it asserts

| violation type | meaning |
|---|---|
| `literal-vs-computed` | A figure typed into the page and a computed one disagree. "Computed" means the value at that DOM path changes across states; "literal" means it never does. Detected (a) for a literal and a computed figure of the same kind on **one visual row** (|dy| < 24px) — `via: "same-row"`, marked heuristic; (b) for elements sharing a `data-figure` or `aria-describedby` key — precise; (c) for a declared `--pair` — precise. |
| `retracted-asserted` | A figure in `facts._retracted.figures` is **asserted** — not struck, with no withdrawal language nearby — in some state. Keyed by `state`: a control that regenerates a withdrawn number shows up only in that control's state. |
| `total-mismatch` | A declared total is not the sum of its declared parts in some state. |

**Mention vs use.** A retracted figure that is struck through (`<del>`, `<s>`, `line-through`) or
sits within a withdrawal sentence ("the old figure, $709, was withdrawn") is being **cited in order
to retract it**. That is the page being honest and is not a finding; it is listed under
`retractedCited` with the evidence (`strikethrough`, or the matched word and its confidence). Strong
withdrawal words are near-conclusive; weak ones ("was", "previously") are suggestive only and the
matched word is reported so you can overrule it by eye.

## Reading the report

`report.json`:

```
{ input, states: [ { name, kind, applied, figures, violations: [types], evidence } ],
  violations: [ { type, state, via?, a: { text, path, value }, b: { ... }, delta } ],
  retracted: [...asserted], retractedCited: [ { figure, replaceWith, states: [ { state, via, word } ] } ],
  coverage: { statesDiscovered, statesApplied, figures, hiddenFigures, auditable, closedShadowCandidates },
  factCheck, vows, worst, verdict, blindSpots }
```

State names are the harness's: `baseline`, `preset=b`, `set:input#units=12`, `toggle:input#rush`.
`worst` is the most severe violation (retracted-asserted, then total-mismatch, then
literal-vs-computed; ties by size of delta). `verdict` is the one sentence to relay.

**Coverage floor.** Fewer than 25 distinct figures across the visited states means the page was
*missed*, not audited. The verdict then reads `COULD NOT AUDIT`, `coverage.auditable` is `false`,
and that is **not a clean result**. Zero violations on a page with no reachable figures proves
nothing.

## Optional vows (`--vows=vows.json`)

A *vow* is a seam check: the page promises something in one place and does what it forbids in
another. Vows are plain data, so a new one costs a JSON row:

```json
[{ "id": "no-forecast", "title": "no forecast figure unless hedged",
   "activate": ["/no forecast/i"], "probe": ["/\\+?50 units a week/i"],
   "discharge": ["/\\b(?:if|might|guess)\\b/i"], "scope": "proximity", "window": 300, "needs": 1 }]
```

The probe corpus is the baseline state; text from every other state is a one-way *softener* that
can withdraw a warning but never create one. Vows are **advisory and never block**; the promise side
is natural language and recall is structurally incomplete.

## Blind spots — carry these into whatever you report

- Only states it was told about, plus controls visible on the **baseline** page, are visited. A state
  behind a drag, a scroll trigger, a form entry or a control revealed only inside another state is
  not reached. Say which states were visited; never claim the rest.
- Range sliders are driven to min and max only.
- `same-row` is a heuristic: a legitimate "list price | 4-unit price" row will trip it. Prefer
  `data-figure` keys and `--pair` when you can declare the relationship.
- Totals are checked only where declared.
- Closed shadow roots cannot be read by anyone (they are counted, not read); figures drawn into
  canvas, SVG paths or images are not text and are not seen.
- A clean result means "no inconsistency in the states and figures it could reach", nothing more.

## Fixtures and self-check

`fixtures/drift.html` is the positive control: a typed `$12.89` beside a slider-driven `$9.39`, a
`?preset=b` that moves the computed value, a rush checkbox that regenerates the retracted `$709` into
the live total (while elsewhere it is struck and labelled withdrawn), a `$1,100` total over `$1,000 +
$90`, and a figure inside a closed `<details>`. `fixtures/consistent.html` is the negative control:
the same page with one source of truth. `node test/run.mjs` asserts the exact violation types, that
the retracted hit appears only in `toggle:input#rush` while the baseline lists `$709` as cited, that
the negative page is clean, and unit-tests the vows engine.
